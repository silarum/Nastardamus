## Исправления безопасности

### C1. Финансовый RPC

- у `public`, `anon` и `authenticated` отозвано право `EXECUTE` на обе версии
  `nastardamus_request_withdrawal`;
- выполнение разрешено только `service_role`;
- функция использует пустой `search_path`, блокировку кошелька и обязательный
  идемпотентный ключ;
- повтор одного запроса возвращает существующую заявку и не создаёт вторую
  проводку;
- журнал проверен: активных заявок и выводов за последние 30 дней нет.

Проверка действующей базы подтверждает:

```text
anon_execute=false
authenticated_execute=false
service_role_execute=true
```

### H1. Повышение административных прав

- право `*` удалено из набора, который можно назначить не-owner роли;
- администратор не может делегировать право, которого нет у него самого;
- серверные проверки не считают сохранённый `*` действительным для
  не-владельца.

### H2. Preview и финансовые операции

- unauthenticated Preview автоматически выключен в Production;
- Preview может получить только демонстрационный нулевой баланс;
- POST на вывод всегда требует подписанный Telegram `initData`.

### H3. Лимиты, повторы и дедупликация

- добавлен устойчивый rate limit в Supabase для AI, помощника и вывода;
- Telegram `update_id` атомарно резервируется и повторно не обрабатывается;
- вывод принимает и проверяет `Idempotency-Key`;
- серверный fallback также передаёт идемпотентный ключ.

### H4. Feature flags и модерация

- добавлен аутентифицированный публичный endpoint конфигурации;
- клиент и API применяют `wheelEnabled`, PalmLink и совместные сценарии;
- фотография модерируется до отправки провайдеру чтения;
- OpenAI Moderation принимает изображение через
  `omni-moderation-latest`; режим manual review блокирует автоматическую
  обработку.

### H5. Согласие на фотографии

- собственное фото требует отдельного подтверждения;
- чужое фото дополнительно требует подтверждения согласия партнёра;
- при включённом `adultOnly` требуется подтверждение совершеннолетия;
- API повторно проверяет согласия, поэтому клиентскую проверку нельзя обойти.

## Исправления среднего риска

### M1. Воспроизводимость Supabase

В репозиторий добавлены:

- `supabase/functions/nastardamus-user-store/index.ts`;
- `supabase/functions/nastardamus-admin-store/index.ts`;
- миграция
  `20260726201005_secure_nastardamus_finance_and_rate_limits.sql`.

В действующем проекте активны `nastardamus-user-store` v2 и
`nastardamus-admin-store` v4.

### M2. Шифрование ключей

Ключ шифрования отделён от Telegram bot token. Используется
`NASTARDAMUS_ENCRYPTION_SECRET`, а безопасный серверный fallback не меняется
при ротации bot token. В базе нет сохранённых custom AI providers, поэтому
миграция существующих секретов не требовалась.

### M3. URL AI-провайдера

Custom `base_url` проверяется в API, runtime и Edge Function:

- только HTTPS;
- запрещены credentials в URL;
- запрещены localhost, private/link-local IP;
- разрешены официальные хосты и явный серверный allowlist.

### M4. Security headers

Для всего приложения добавлены CSP, HSTS, `nosniff`, Referrer-Policy и
Permissions-Policy. Заголовок, блокирующий Telegram WebView, не используется.

### M5. Устаревшие медиа

После проверки ссылок удалены заменённые PNG-карты, старые фоны и
`video/welcome.mp4`. Активные WebP и `welcome-v2.mp4` сохранены. Из публикации
исключено примерно 83 МБ неиспользуемых дубликатов.

### M6. Bot ID и Telegram `getMe`

Bot ID вынесен в `NASTARDAMUS_APP_BOT_ID`. Результат `getMe` кешируется на
10 минут по SHA-256 отпечатку токена, не сохраняя токен в логах.

### M7. Индексы внешних ключей

Добавлены индексы:

- `nastardamus_ai_agents.provider_id`;
- `nastardamus_ai_agents.fallback_provider_id`;
- `nastardamus_support_tickets.assigned_admin_id`.

## Исправления низкого риска

- настройка пользовательского и административного webhook требует
  `X-Webhook-Config-Secret`;
- готовность readings учитывает OpenAI и OpenRouter;
- в интерфейс добавлено удаление локальной истории;
- `aria-live` удалён со всего корневого приложения и оставлен точечным статусам.

## Supabase: итоговая проверка

Security Advisor больше не сообщает о публично исполняемых
`SECURITY DEFINER`-функциях. Оставшиеся INFO-сообщения
`rls_enabled_no_policy` относятся только к серверным таблицам rate limit и
дедупликации: RLS включён, права `anon`/`authenticated` отозваны, доступ имеет
только `service_role`. Новые индексы могут временно отображаться как unused,
пока Production не накопит обращения.
